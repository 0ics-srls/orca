Computer-use helper process reaping

Issue: #9141   Verified: 2026-09-15   Worktree: computer-use-spawns-200-unmanaged-helper-process

Claim under test

Detached macOS computer-use helpers must not accumulate when requests time out, sockets fail or close, startup is superseded, or Orca shuts down. Each spawned process is owned immediately, receives SIGTERM during teardown, and receives SIGKILL after a 2-second grace period only if still alive.

Implementation evidence

InvariantProof in code
Ownership begins at spawnstartMacOSNativeProviderSocket calls providerProcess.adopt(provider) immediately after spawnProvider.
Replacement cannot strand the old generationMacOSProviderProcessOwner.adopt reaps its existing handle before replacing it.
Safe signal targetreapMacOSProviderProcess signals the ChildProcess object, never a numeric pid.
EscalationSynchronous SIGTERM, then SIGKILL at PROVIDER_SIGKILL_GRACE_MS = 2000 if exitCode/signalCode remain unset.
Exactly onceModule-level WeakSet<ChildProcess> prevents duplicate signals/timers across overlapping teardown paths.
All client teardown pathsShutdown, socket close, transport error, and write failure call releaseHelperGeneration(), which reaps the owner.
