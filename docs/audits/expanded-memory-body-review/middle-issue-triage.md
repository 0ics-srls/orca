# Middle-numbered issue body review

Read all 40 bodies and 54 comments for new candidates numbered 11000–15999. Cached pagination was complete; every body/comment hash matches the discovery index. No network or attached-code execution was needed.

This review separates measured resource incidents, ownership and visibility gaps, bounded policy requests, and lexical false positives. Author hypotheses remain attributed and later corrections take precedence. No product changes were made.

## Findings that change the audit

- **#12845:** measured renderer heap 2.1–2.7 GiB plus crash;2142 editor rows serialize to only~3.9 MiB. Historical duplicate restoration is relevant, but row counts do not identify the large payload owner.
- **#13047 / #13678 / #15146:** live external processes, stale ledger records, and unowned detached descendants are different lifetimes. Settled dispatch or missing UI row is not permission to terminate user-owned work.
- **#14592 / #14999:** concrete external Grok/MCP resource costs accompany feature requests. They do not prove an Orca JS heap leak.
- **#14882:** compositor CPU incident explicitly has stable 66–99 MB JS heap. **#12596** slow parking churn is not automatically covered by current 1 s burst damping.
- **#15987:** merged#16106 already replaces whole-file staging with 384 KiB streaming. Its latest comment distinguishes main from the released build. **#15352:** current shutdown code includes the reported#16497 correction.
- **#14641:** mobile duplicateQueued state needs a remaining-path control after existing 14936/17783 reconciliation. **#15833:** current Codex POSIX hook still waits forEOF; a small held-stdin proof can establish the conditional liveness mechanism without asserting memory growth.
- **#14210:** environment-removal exception overlaps the separately reviewed 20995/reporterPR 21048; avoid duplicate implementation.
